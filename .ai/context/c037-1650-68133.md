The open items the revamp design deliberately left open, plus two

## Decisions

1. **Shipped default epoch: `2026-01-01T00:00:00Z`.** Start of 2026,
   UTC. `tools/.epoch` ships this value, and the new id format's
   7-digit minute counter is measured from it. Supersedes the earlier
   `2026-08-28 01:27:20 -0300` default; already-minted ids are not
   ported (no backward compatibility required).
2. **Router skill name: `route`.** The skill in front of the
   per-operation skills — plain-language request in, points to the
   correct operation skill.
3. **Final template set (7 files):**
   - `task-template.md` (new — the design's task-file layout, exact)
   - `context-item-template.md` (new — `c-{ID}` items, incl. the
     decision shape with relation/superseded-by)
   - `context-template.md` (updated — now the `context.md` index:
     mission + techstack core inline and the index table)
   - `assumptions-template.md` (renamed from
     `context-temp-template.md` — the assumptions file for
     ground-up context building)
   - `info-template.md` (kept, updated)
   - `workbench-readme-template.md` (kept)
   - `context-build-plan-template.md` (kept, updated)
   Removed: `adr-template.md`, `decisions-template.md` (decisions
   are context rows now).
4. **No Owner field.** The design's Teams section is implemented
   without an owner/assignment column; coordination is the
   file-overlap rule plus git as the sync layer.
5. **Workspace pilots the new model for the revamp task.** The
   workspace's `.ai/` tree is still on the old installed workflow,
   but the revamp task and this decision record use the new form:
   new ids, new statuses, the folder shape under `.ai/tasks/`,
   decisions as `c-{ID}` context rows. The rest of the tree is
   migrated by the follow-up migration task, not this one.

## Rationale

The design left the epoch, router name, and template set open
deliberately (ask-don't-invent). Values chosen for minimal churn:
epoch at a clean year boundary, a router name that states its job,
template names that describe the artifact. The Owner field is
dropped because file-overlap visibility already makes conflicts
visible without an assignment column. The pilot (5) lets the revamp
task live entirely in the target model while the old workflow keeps
working elsewhere in this tree until migration.
